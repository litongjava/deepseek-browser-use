# 商户申请与多层验证表单经验

本分册适用于用户已授权办理的商户申请、支付应用创建和配置。它不授予额外的支付、转账或对外消息权限。

## 表单与弹窗

- 多层弹窗中的背景按钮也可能满足 `isVisible`。`button[type=submit]` 不一定是当前验证码的确认按钮。先读新快照，优先用当前弹窗中的索引或带弹窗范围的选择器。
- auto 点击遇到遮挡不再穿透。不要为了消除错误直接改为 `mode=js`；先确认遮挡层的任务是否需要完成。
- `Object doesn't exist: request@… / response@…` 可能在点击已经发出后出现。动作不自动补点；读取结果、页签和业务状态后决定下一步。创建应用、提交审核尤其要先检查是否成功，避免重复创建。
- 上传图标可能弹出裁剪窗口。`filesLength=0` 可能表示框架已消费文件，不应重复上传；完成裁剪并回读图标展示后再提交。
- 自定义商家下拉框的 input value 可能为空，选择是否生效应结合可见企业名称判断。提交前核对主体、应用类型、官网和简介。

## Windows 参数传递

包含中文、引号的 CSS 选择器或多行脚本时，优先用 UTF-8 JSON 文件传参，避免 `.cmd` 转义导致中文丢失、属性引号被剥掉。即使回执为 `committed=true`，关键字段仍要回读。

```powershell
@{selector='#appName';text='示例应用';mode='type'} |
  ConvertTo-Json | Set-Content tmp/app-name.json -Encoding utf8
dsb --port 10049 --id 1001 run input_text_by_selector --params '@tmp/app-name.json'
```

## 人工验证与密钥

首次联系人验证、产品申请验证和密钥保存验证可能各自使用不同短信。验证码只用于当前流程，失败后先读平台错误，不把旧码用于下一流程。需要本人操作时按 `human-in-loop.md` 请求协助，等待期间不刷新或再次发送。

私钥仅在用户授权的本地或服务器目录生成，已有密钥不能无提示覆盖。只向官方应用配置上传应用公钥；下载的是支付宝公钥，与应用公钥不同。保存后核对页面显示的应用公钥与本地密钥配对，并以平台成功信息为准。

产品“审核中”、应用“审核中”、密钥“已设置”分别记录。任何一项成功都不能替代其他项或真实支付验证。已授权的独立准备工作可以继续，需人工验证码的那一步则等待真实答复。

## 对外总结前脱敏

技能和公共教程使用虚构企业名、`example.com`、`YOUR_APP_ID`、`YOUR_SELLER_ID` 等占位符。不要复制真实手机号、短信验证码、证照、账号、AppID、密钥、签名链接或本地个人资料路径。

客户端仅对自动留档中的结构化 Cookie 值做定向遮蔽；实时输出、`data/`、截图、trace、临时 JSON 和其他敏感字段仍可能包含原文。原始留档仅用于本地核验，不整段复制到公共文档；公开前检查正文、页签 URL、图片与文件名。公钥不属于私钥，但教程没有必要包含真实应用公钥。
