# 中国政府网站查资料

适用于**省/市/县/局各级政务网站**上查公告、批复、公示、征地信息、招标结果这类资料。这类站点大多是同一批 CMS 做的：一个全文检索入口、一套「政府信息公开」栏目树、公告正文常常是**扫描件或图片**。

工具侧的通用能力见主技能文档；本文只讲**这类站点上必须怎么做**。

## 一、站内检索：**必须走表单，别拼 URL** ⭐ 最容易白跑的一趟

这类站的检索参数（关键词、精确/模糊、日期区间、每页条数）**全在页面 JS 的状态里**。直接打开

```text
/s?as=true&qal=关键词&bt=2022/01/01&et=2022/12/31&p=2
```

这种带参 URL，页面加载完会**用自己的状态覆盖掉参数**，然后老老实实告诉你「共 0 条信息」——**它不报错，只是静默地什么都没搜**。实测照这个 URL 查一个明明存在的年份区间，得到 0 条，据此差点得出「该年没有这份文件」的结论。

正解是两条：

1. **用配方**（推荐）：`run_recipe` 跑 `gov-site-search`，它会填表、点搜索、等稳定、再把结果读回来；
2. **自己走一遍**：先 `go_to_url` 到高级搜索页（通常是 `/s?ac=a`），用 `click_element_by_selector` / `input_text_by_selector` 填控件，最后**真实点击**搜索按钮。

### 表单上那几个开关

| 控件 | 作用 | 建议 |
| --- | --- | --- |
| `searchWayText` | 关键词输入框 | 直接填 |
| `searchWay` | 匹配方式 | 见下 |
| `ultimetype` | 时间范围 | 选「指定日期」后才认 `begintime` / `endtime` |
| `begintime` / `endtime` | 日期区间 | 形如 `2022-01-01`，填完页面自己会规范化 |
| `pagesize` | 每页条数 | **直接选 50**，多数时候一页就能看全，省掉翻页 |

**匹配方式三档，默认那档最坑**：

| 取值 | 界面文字 | 实际行为 |
| --- | --- | --- |
| `queryand` | 包含全部关键词 | 默认档。按空格拆词做 AND，**但分词很粗** —— 实测搜「未利用地」会返回一堆只含「利用」的无关文件 |
| `queryall` | **包含完整关键词（不按空格拆分关键词）** | **要查一个具体说法就用它**，最接近「精确短语」 |
| `queryor` | 包含任意一个关键词 | 极少用 |

> 结论：**默认档会把无关结果混进来，让你误判「查到了」；而带参 URL 会让你误判「没查到」。** 两个方向都会错。

### 翻页

结果页的页码不是 `href` 链接，而是 `data-locationhref="s?as=true&qal=…&p=2"` 这种属性 + JS 跳转。所以：

- 点页码用 `click_element_by_selector`，选择器写 `a[data-ui='fulltextsearchpagebutton'][data-locationhref*='p=2']`；
- **注意它会同时命中「页码 2」和「下一页」**（两者 href 一样），回执里的 `matched` 会告诉你命中几个；要指定就用 `nth`；
- 更省事的办法是**一开始就把 `pagesize` 拉到 50**，通常一页就完了。

## 二、读到公告之后：正文、表格、图片三条路

| 页面上是什么 | 怎么读 |
| --- | --- |
| 普通正文 | `extract_structured_data`（纯文本）或 `extract_markdown`（要保留结构） |
| **表格**（补偿标准、地类面积、成交结果） | 先 `list_tables` 看有几张、哪张是你要的，再用它给的 `selector` 调 `extract_markdown`。**别用纯文本那条** —— `innerText` 会把单元格逐行摊平，列对不上 |
| **整页是图片/扫描件**（公告正文、明细表、批复附件） | `download_image` 把**原始文件**取到服务端，再用 `ocr_image` 读。`innerText` 对这类内容**一个字都读不到**，换多少选择器都没用 |
| 只想找其中一行（文号、某个乡镇） | `find_text`，别把整页拉回上下文 |

**怎么知道该走哪条**：`get_browser_state` 的回执里有 `mediaCount` / `mediaHint` —— 非空就说明这页有大图，内容很可能在图里。这是这类站点最值钱的一条提示。

> 实测教训：一份政府公告的关键数据（建设用地明细表）**整份是图片附件**，正文只写了「详见附件」。前面几轮一直在正文里换选择器找数字，方向从一开始就是错的。

## 三、征地类信息的栏目地图

县/市自然资源部门的「政府信息公开」下通常有这几栏，**内容完全不同**，别混：

| 栏目 | 里面是什么 | 有没有地类面积 |
| --- | --- | --- |
| 征收土地预公告 | 拟征收范围（乡镇/村） | 通常没有 |
| 征地补偿安置方案公告 | **按乡镇、村、村民组的权属/地类/面积表** + 补偿标准 + 安置途径 | **有**（农用地各细类、建设用地、未利用地） |
| 征收土地方案公告 / 征收土地公告 | 批准后告知：项目、位置、被征收单位权属与地类面积、补偿标准 | 有 |
| 征地批准文件 | 省政府/市政府的批复转发件 | 批复正文里常有「转用并征收集体农用地 X 公顷」 |
| 农用地转用方案 | 转用面积表（农用地/未利用地） | **有**，且常带明细表**图片** |
| 划拨用地批前公示 / 结果公示 | 宗地编号、面积、坐落、用途、受让单位 | **没有**（这是供地环节） |

**「在某某乡占了多少地」这类问题，答案在「征地补偿安置方案公告」或「一书四方案」里**，不在划拨公示里；而划拨公示只有宗地面积，往往只是全项目的很小一部分（实测三宗合计不到全项目的 1%）。

## 四、数字到底在哪：批准文件 ≠ 公告

同一个项目会有一串文件，**文号各不相同、内容粒度也不同**：

```text
自然资源部批复（自然资函〔20XX〕XXX 号）      ← 全项目的地类面积，最权威
  └─ 省厅函（豫自然资函〔20XX〕XXX 号）         ← 转发，通常含同样的数字
       └─ 市政府转发通知（X政土〔20XX〕XXX 号）  ← 正文往往只有一句"请按批复履行批后程序"，
                                                  数字在**附件 PDF** 里
            └─ 县政府：征收土地公告 / 征地补偿安置方案公告  ← 按乡镇/村拆开
```

写检索式或写依申请公开时**别把这几份混为一谈**：拿「批复的文号」去指代「征地补偿安置方案公告」会被一句"已提供"顶回来。

另外注意：**县级政府的这类公告常常没有发文字号**（页面上的「文号」字段是空的），此时用「**文件名称 + 落款日期 + 项目名称**」来特定 —— 这是《政府信息公开条例》认的「其他特征性描述」。

## 五、中文检索的两个坑

1. **形近字/异体字**。实测一份公告把「**褚**庙乡」印成「**禇**庙乡」（不同字），按常用字检索整段漏掉，几乎得出「没有这回事」的结论。查人名、地名、乡镇名时**两个写法都搜一遍**，或者在结果里按拼音/偏旁再核一次。
2. **编号里的数字**。站内检索对长数字（文号、索引号、宗地编号）的分词不可靠，用 `queryall` 精确短语并且**只搜数字本身**，不要带前后缀。

## 六、站上确实没有时：转依申请公开

如果逐栏核对 + 全文检索 + 精确短语检索都确认**没有**，不要就此收尾 —— 政府信息有「主动公开」与「依申请公开」两条腿。写申请时把这几样写进去：

- **特征性描述**：文件名称、落款日期、项目名称、所涉乡镇与村名、材料类别（一书四方案 / 征收土地方案 / 补偿安置协议）；
- **检索范围说明**：写明你已经在哪个网站的哪些栏目、用什么关键词、什么时间范围查过 —— 这会让「信息不存在」的答复必须**说明检索范围与方式**；
- **请求公开属性说明**：若不予公开，要求书面说明理由与依据。

## 七、检查清单

```text
□ 检索走的是表单（不是带参 URL）
□ 匹配方式切到「包含完整关键词」（queryall）
□ 需要年份区间时，ultimetype 切到「指定日期」并填了起止
□ pagesize 拉到 50，先看总数再决定要不要翻页
□ 结果里的日期是「成文日期」还是「发布日期」—— 相差几个月很常见
□ 打开公告后先看 get_browser_state 的 mediaHint：有大图就先 download_image
□ 有表格用 list_tables + extract_markdown，不用纯文本
□ 乡镇名/人名换形近字再搜一遍
□ 确认没有 → 记下查询路径，转依申请公开
```
